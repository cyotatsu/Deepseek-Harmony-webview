## 关键行为

### 窗口形态与网页布局

**布局视口始终等于应用窗口宽度**，而不是屏幕宽度。浏览器里 `device-width` 指的是屏幕宽度，
悬浮窗 / 自由多窗下窗口远窄于屏幕，页面会按整屏排版再整体缩小（看起来「UI 变小」），
因此应用在页面加载完成与窗口尺寸变化时，把网页 viewport 的 `width=` 段改写为窗口宽度。
窗口变化只防抖补发 `resize` 事件，**不重载页面**，拖拽窗口时不会闪烁或丢失正在输入的内容。

> 全屏下对话区两侧留白很大、内容看着偏小是**正常的**：站点自身的会话列有固定
> `max-width`（约 768px）并居中，屏幕越宽留白越多 —— 页面并没有被缩放。

### 软键盘与输入框

- 输入框高度上限由脚本按**实时可视高度**算出，长文本不会再把它顶到无限高，
  也不会出现「输入区与发送按钮之间大片空白、底部工具栏被裁掉」；
- 点图片不会再意外弹出键盘（内核开关 + 捕获阶段防护脚本两层处理）；
- 键盘弹出时窗口收缩、网页同步重排，输入框始终短于当前可显示区域；
- **编辑历史消息时隐藏主对话框**：键盘弹出、且焦点在消息气泡里的编辑框（而不是底部固定栏）时，
  给底部主对话框加 `ds-composer-hidden`（`display:none`）让位，并把编辑中的元素滚动到可视区中央；
  焦点 / 尺寸变化时自动复查，退出编辑或收起键盘即恢复。判定全靠结构（底部固定容器、
  焦点是否在其中），不依赖站点的哈希类名。
  > 主对话框的定位有个坑：进入编辑态后，站点会把主输入框换成**占位元素**（不再是
  > `textarea`），于是「找另一个可编辑元素再向上找底栏」这条路会落空 —— 实测表现为
  > `inlineEdit` 判对了、`hasCard` 却是 `false`，什么都没隐藏。因此补了一条**独立的几何扫描**
  > （`fixed`/`sticky` 且底边贴可视区底部、宽不小于半屏、高不超过半屏，取面积最大者），
  > 并记住被隐藏的元素（它已 `display:none`，几何扫描会跳过它，不记住就再也恢复不了）。
  > 键盘状态由**应用侧**推入网页（`avoidAreaChange` 的 `TYPE_KEYBOARD` 底部避让高度）：
  > 网页自己只能靠「可视高度变小」推断，而自由多窗 / 悬浮窗拖拽同样会让可视高度变小，分不开。
- **编辑卡片的取消 / 保存按钮始终留在可视区内**：历史记录含图片 + 编辑长文本时，
  卡片的整体高度没人管（原先只压了 `textarea` 与「直接子元素」），图片和外层留白会把
  按钮挤出屏幕。做法是给「内联编辑卡片」加 `ds-inline-editor`，用 CSS 把它变成
  **列向 flex + 限高**（上限 = `clamp(120px, 55% × 可视高度, 420px)`，绝对上限保证
  电脑 / 2in1 大屏上不会被算得过大）：文本框吸收收缩并自己滚动、按钮行固定留在卡片内；
  卡片里的图片另按 `20vh` 限高，不参与顶高。滚动改用 `scrollIntoView({block:'end'})`，
  让卡片底部（按钮行）对齐可视区 —— 居中反而可能把按钮推到键盘后面。
- **编辑时点输入框必定聚焦**：卡片里除文本域还有留白，站点没把点击转发给文本域，
  于是「点了没反应」。注入脚本在编辑卡片范围内监听 `pointerdown`：落点不是可交互元素时，
  把焦点补到文本域上（用户手指天然带 user activation，键盘能正常拉起）。
- **键盘没弹起来时的兜底**：网页通过约定的 `console` 前缀 `__dsFocus:` 把
  「可编辑元素获得焦点」上报给应用侧（`onConsole`），应用侧等 350ms 若发现键盘确实没起来
  （`keyboardHeightVp` 仍为 0）就依次尝试：
  ① `inputMethod.getController().showTextInput(RequestKeyboardReason.TOUCH)` —— 它
  **不需要系统权限**（`showSoftKeyboard()` 需要 `ohos.permission.CONNECT_IME_ABILITY`，
  普通应用调用会抛 201，不能用）；
  ② 临时把键盘策略切回 `DEFAULT` 并让网页 `blur()+focus()` 重新聚焦，让内核的焦点驱动路径生效；
  用完立即恢复 `DISABLE_AUTO_KEYBOARD_ON_ACTIVE`（那是「点图片不弹键盘」的防线）。
  另外网页侧对编辑框做了**焦点自愈**：异步渲染把焦点顶掉时补一次 `focus()`
  （只在真的丢了、且没有别的可编辑元素接管时才补，避免打乱光标）。

### 返回手势（侧滑返回 / 返回键）

| 当前状态 | 返回行为 |
|----------|----------|
| 网页弹窗（设置、分享等） | 交给网页后退，即关闭弹窗 |
| 网页的临时界面：会话「…」菜单、账号菜单、侧栏「选择对话」多选模式 | **点掉它** —— 优先点它自己的「关闭」入口，没有则模拟点一下菜单外面 |
| 对话界面（首页、会话页），且没有上述界面 | 不后退，提示「再按一次返回桌面」，2s 内再按一次才退出 |
| 站内其他页面（`/sign_in`、`/share/…`） | 网页后退，与默认行为一致 |
| 应用自己的弹层（上传 / 设置面板） | 优先关闭弹层 |

> **为什么要分成这几类**（都是实机测出来的，不能只看「网页能否后退」）：
> 网页弹窗（实测元素为 `ds-modal`）打开会多出一条历史（`histLen` 1→2），后退就是它的
> 关闭动作；它的关闭按钮**没有 aria-label**、模态弹窗又盖满屏幕点不到「外面」，
> 所以 DOM 点不掉，只能用后退。而**会话菜单与多选模式完全不进历史**
> （`histLen` 始终为 1，且 Esc 无效），后退关不掉它们，只能点掉；反过来，
> 仅仅「切换到一个历史会话」也会让历史变成 2，所以「有没有历史」既不能证明有弹层、
> 也不能证明该不该交给网页。判定依据是 DOM：弹窗有 `role="dialog"` / `aria-modal`，
> 菜单有 `role="menu"`，「关闭 / 取消」入口分两种形态：平板的「选择对话」是
> `aria-label="关闭"` 的图标按钮，手机的「选择对话 / 分享选择（创建分享链接）」顶部是
> **纯文字「取消」**（没有 aria-label）—— 所以文字这一路也要认：
> **叶子节点 + 整段文字正好是「取消 / 关闭」+ 像按钮的尺寸**。
>
> 点掉菜单的顺序：① 它自己的「关闭」入口（含上面那种纯文字「取消」）→
> ② 处于展开态的触发按钮（`aria-expanded="true"`，再点一次即收起）→
> ③ 把「点外面」的点击**派发到 `body`**。
>
> **不能按坐标去点内容区，更不能去点那层全屏遮罩**：实测那层遮罩属于**侧边栏抽屉**。
> 宽屏下侧栏是常驻列、内容区在它右边，按坐标点没事；但**窄屏（手机 / 平板非全屏）侧栏就是
> 抽屉、内容区正好被它盖住**，按坐标点过去会命中遮罩 —— 表现就是「菜单关了，侧栏也被
> 一起收起」。派发到 `body` 则不同：事件仍冒泡到 `document`（挂在那里的「点外部关闭」
> 收得到），而遮罩不在 `body → document` 的路径上，它的「收起侧栏」处理器不会触发，
> 于是菜单关闭而侧栏保持展开。
>
> 由于查 DOM 是异步的，返回事件固定被消费，退出到桌面由应用主动结束 Ability 完成。
> 每次决策都会打一行 `Back action`，其中的 `detail=` 给出**触发判定的那个元素**
> （`类别|标签|role|class|宽x高`），换设备/换窗口形态出问题时可直接据此定位。

### ⚠️ 工程路径不能包含空格

DevEco 的工程路径只允许字母、数字、`.`、`_`、`-`。路径带空格时 hvigor 命令行构建**完全正常**，
但 IDE 侧工程模型解析失败（`module src path is not valid`、`module model size: 0`），
表现为**运行配置的 Module 下拉为空、点 Run 报 `No module found`**。
清缓存、重装 DevEco 都无效 —— 只有把工程移到无空格路径（如 `D:\DevEcoProjects\...`）才能解决。

### 关于签名配置

签名证书的本机绝对路径与加密口令只存在于本地，**不在仓库里**。直接 clone 后无法构建，
需先在 DevEco 里重新配置：**File → Project Structure → Signing Configs → Automatically generate signature**。

## 已知限制

| 限制 | 说明 |
|------|------|
| 浏览器深链不唤醒 | `chat.deepseek.com` 非自有域名，无法托管 AGC 域名校验文件，故浏览器里点同域链接不会唤起本应用（从其他 App / 扫码仍可） |
| base 资源为简体中文 | 资源目录为 `base`(简中) / `en` / `en_US` / `ru` / `zh_HK`。德语、法语、日语等**未覆盖**的系统语言会回退到 `base`，即显示简体中文 |
| 不创建新窗口 | 单 Web 组件架构，`window.open` 不另开窗口：站内地址在当前 Web 内导航，站外地址转系统浏览器 |
